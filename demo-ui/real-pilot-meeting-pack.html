Real Pilot Meeting Pack V1

Use this the moment a clinic replies.

The goal is not to sell AI or blockchain. The goal is to test whether a clinic can verify the pet + owner consent and receive only a short VetBrief instead of reconstructing the whole context from scattered messages and records.

Boundary: no diagnosis automation, no replacement of veterinary judgement, no government endorsement claim, no full CAIOS Memory disclosure.

15-minute discovery

  1. What information is usually missing?
  2. How much time is spent reconstructing context?
  3. Which home observations are useful vs noise?
  4. What would make an external summary trustworthy?
  5. What privacy boundary is required?
  6. Would verified pet identity + explicit consent help?
  7. Who would own a 20–30 minute pilot?
  8. What conditions must be true before trying one real pet?
Meeting score helps prioritise. High score never equals pilot acceptance.

Explicit acceptance

Do not infer acceptance from interest or a good score. Ask directly:

Are you comfortable for us to run one 20–30 minute real-pet pilot with your clinic, using only the vetbrief:summary scope, with explicit owner consent and a revocation / negative-control test?
Record PILOT_ACCEPTED only after an explicit affirmative answer and an identified pilot contact.

20–30 minute live pilot

  1. Confirm clinic + pilot contact
  2. Confirm real pet + owner consent
  3. Verify signed credential + issuer policy
  4. Verify relationship / consent
  5. Produce bounded trust assertion
  6. Release only VetBrief summary
  7. Measure workflow duration
  8. Measure information completeness
  9. Capture follow-up readiness
  10. Revoke consent / credential
  11. Execute negative control
  12. Confirm release is blocked
  13. Run privacy audit
  14. Append ledger evidence
  15. Assemble final bundle
  16. Run Issue #8 Closure Gate
